## Findings to fix before the integrated demo

1. **Requester login lands on a forbidden page (Budoor).**
   app/actions/auth.ts:22 and app/auth/login/page.tsx:8 redirect every active user to /assets.
   app/assets/page.tsx:12 permits only custodian/admin/approver. A requester-only account logs in,
   then immediately sees access denied. Redirect to /search or an authorized role-specific page.
   This does not require changing any database table.

2. **Inactive custodians retain direct read access to their assets (Budoor).**
   supabase/migrations/20261114090000_budoor_access_and_assets.sql:86-90 has a standalone
   custodian_id = auth.uid() alternative. Disabling app_user.account_status does not make an
   already issued Auth session disappear, so that alternative still permits asset/history reads.
   Add an active-profile gate around the complete policy in a NEW migration and test an existing
   inactive user's session. Consider active-department gating consistently across operations too.

3. **Publish authorization has a nullable-condition edge case (Budoor).**
   In publish_asset, if an active custodian targets an asset in another department whose
   custodian_id is NULL, `(custodian_id = auth.uid() OR department_id = current_department_id())`
   evaluates to NULL. `IF NOT (...)` also becomes NULL and does not raise the exception.
   Reject unless the whole permission expression `IS TRUE`, or coalesce it to false.
   The asset schema allows a null custodian, so SQL setup or future transfers can expose this case.

4. **AI ranking differs from the submitted design (Shaikha).**
   app/protected/requests/rank-assets.ts:78-90 asks Gemini to invent an illustrative 0–100 score.
   Phase 4–5 section 8.11.2 specifies weighted factors, deterministic calculation, missing-evidence
   handling and evidence coverage. Also the eligibility SQL checks stock/category/condition but
   not structured mandatory specifications, required-date feasibility or inspection requirements.
   These are design/implementation gaps, not evidence that existing scores satisfy the SRS.
   Implement the documented calculation/eligibility or record an instructor-approved simplification.

5. **Database errors look like empty data or missing assets (Budoor).**
   lib/services/AssetService.ts:getById, getHistory, search and listManaged discard error and return
   null/empty arrays. A permission or query failure can show a misleading 404 or 'No assets'.
   Return a distinct load error and display a retry/setup message. Similar checks apply to admin lists.
